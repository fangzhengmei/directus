## 1. 概述

Directus 的实时订阅功能基于 WebSocket 协议实现，允许客户端订阅数据集合的变更事件。当服务端数据发生变更时，相关订阅方会收到实时推送的变更通知。

### 核心组件

- **服务端 (API)**:
  - `api/src/websocket/handlers/subscribe.ts` - 订阅处理器
  - `api/src/websocket/controllers/hooks.ts` - 事件钩子注册
  - `api/src/websocket/messages.ts` - 消息类型定义

- **客户端 (SDK)**:
  - `sdk/src/realtime/composable.ts` - 实时功能核心实现
  - `sdk/src/realtime/types.ts` - 类型定义

- **前端应用 (App)**:
  - `app/src/composables/use-collab.ts` - 协作编辑功能示例

## 2. 客户端订阅机制

### 2.1 建立 WebSocket 连接

客户端通过 SDK 的 `realtime()` 插件建立 WebSocket 连接：

```typescript
// sdk/src/realtime/composable.ts:60-69
const sdk: SdkClient & WebSocketClient<unknown> = baseSDK.with(
    realtime({
        authMode: 'strict',
        connect: false,
        reconnect: {
            delay: 10000 + Math.floor(Math.random() * 5000),
            retries: Infinity,
        },
    }),
);
```

**连接流程** (`sdk/src/realtime/composable.ts:245-353`):

1. **构建 WebSocket URL**:
   - 从主 URL 推断 WebSocket 端点
   - HTTP → WS, HTTPS → WSS
   - 默认路径: `/websocket`

2. **认证模式** (三种可选):
   - `public`: 无需认证
   - `handshake`: 连接后发送认证消息
   - `strict`: URL 中携带 `access_token`

3. **自动重连机制**:
   - 连接断开时自动尝试重连
   - 可配置重试次数和延迟
   - 重连后自动恢复所有订阅

### 2.2 发送订阅请求

客户端通过 `subscribe()` 方法订阅数据集合：

```typescript
// sdk/src/realtime/composable.ts:400-473
async subscribe<Collection extends keyof Schema, const Options extends SubscribeOptions<Schema, Collection>>(
    collection: Collection,
    options = {} as Options,
) {
    // 1. 生成唯一订阅 ID (uid)
    if ('uid' in options === false) options.uid = uid.next().value;

    // 2. 转换查询参数
    if (options.query) {
        options.query = queryToParams(options.query);
    }

    // 3. 记录订阅（用于重连恢复）
    subscriptions.add({ ...options, collection, type: 'subscribe' });

    // 4. 确保连接已建立
    if (state.code !== 'open') {
        await this.connect();
    }

    // 5. 发送订阅消息
    this.sendMessage({ ...options, collection, type: 'subscribe' });
    
    // 6. 返回异步生成器用于接收事件
    return {
        subscription: subscriptionGenerator(),
        unsubscribe,
    };
}
```

**订阅消息格式** (`api/src/websocket/messages.ts:38-50`):

```typescript
{
    type: 'subscribe',           // 消息类型
    collection: 'articles',      // 要订阅的集合
    event?: 'create' | 'update' | 'delete',  // 可选：过滤特定事件类型
    item?: string | number,      // 可选：订阅特定项目
    query?: Query,               // 可选：查询参数（用于过滤返回数据）
    uid?: string | number        // 订阅唯一标识
}
```

**订阅选项说明**:

| 选项 | 类型 | 说明 |
|------|------|------|
| `event` | `'create' \| 'update' \| 'delete'` | 只接收特定类型的变更事件 |
| `item` | `string \| number` | 只订阅特定 ID 的项目变更 |
| `query` | `Query` | 定义返回数据的字段、过滤条件等 |
| `uid` | `string \| number` | 订阅唯一标识，用于匹配返回的事件 |

### 2.3 订阅消息生成器

订阅返回一个 `AsyncGenerator`，用于持续接收事件：

```typescript
// sdk/src/realtime/composable.ts:420-461
async function* subscriptionGenerator(): AsyncGenerator<SubscriptionOutput> {
    while (subscribed && state.code === 'open') {
        // 等待消息
        const message = await messageCallback(state.connection);
        
        if (!message) continue;

        // 检查是否为订阅相关的消息
        if (
            'type' in message &&
            'uid' in message &&
            message['type'] === 'subscription' &&
            message['uid'] === options.uid  // 匹配订阅 ID
        ) {
            yield message;  // 产出事件
        }
    }

    // 重连后自动恢复订阅
    if (config.reconnect && reconnectState.active) {
        await reconnectState.active;
        if (state.code === 'open') {
            state.connection.send(JSON.stringify({ ...options, collection, type: 'subscribe' }));
            yield* subscriptionGenerator();
        }
    }
}
```

### 2.4 取消订阅

```typescript
// sdk/src/realtime/composable.ts:463-467
const unsubscribe = () => {
    subscriptions.delete({ ...options, collection, type: 'subscribe' });
    this.sendMessage({ uid: options.uid, type: 'unsubscribe' });
    subscribed = false;
};
```

## 3. 服务端订阅识别和通知机制

### 3.1 服务端订阅管理

服务端通过 `SubscribeHandler` 类管理所有订阅：

```typescript
// api/src/websocket/handlers/subscribe.ts:17-38
export class SubscribeHandler {
    // 按集合存储订阅：collection -> Set<Subscription>
    subscriptions: Record<string, Set<Subscription>>;
    
    // 内部消息总线（用于多实例部署）
    protected messenger: Bus;

    constructor() {
        this.subscriptions = {};
        this.messenger = useBus();
        this.bindWebSocket();

        // 监听 Redis 发布/订阅通道
        this.messenger.subscribe('websocket.event', (message: Record<string, any>) => {
            try {
                this.dispatch(message as WebSocketEvent);
            } catch {
                // 忽略无效消息
            }
        });
    }
}
```

### 3.2 注册订阅

```typescript
// api/src/websocket/handlers/subscribe.ts:64-76
subscribe(subscription: Subscription) {
    const { collection } = subscription;

    // 某些系统集合不支持订阅特定项目
    if ('item' in subscription && ['directus_fields', 'directus_relations'].includes(collection)) {
        throw new InvalidPayloadError({ reason: `Cannot subscribe to a specific item in the ${collection} collection.` });
    }

    // 按集合分组存储订阅
    if (!this.subscriptions[collection]) {
        this.subscriptions[collection] = new Set();
    }

    this.subscriptions[collection]?.add(subscription);
}
```

            action: 'create',

            collection,
            action: 'update',
            keys,

            collection,
            action: 'delete',

function registerAction(event: string, transform: (args: Record<string, any>) => WebSocketEvent) {
    const messenger = useBus();

    emitter.onAction(event, (data: Record<string, any>) => {
        // 通过 Redis 发布/订阅广播事件
        // 这支持多实例部署，所有实例都能收到变更通知
        messenger.publish('websocket.event', transform(data) as Record<string, any>);
    });
}

### 3.4 事件分发到订阅方

当收到 `websocket.event` 消息后，`SubscribeHandler` 负责分发给相关订阅方：

```typescript
// api/src/websocket/handlers/subscribe.ts:108-135
async dispatch(event: WebSocketEvent) {
    // 1. 获取该集合的所有订阅
    const subscriptions = this.subscriptions[event.collection];
    if (!subscriptions || subscriptions.size === 0) return;
    
    const schema = await getSchema();

    // 2. 遍历所有订阅，检查是否匹配
    for (const subscription of subscriptions) {
        const { client } = subscription;

        // 2.1 检查事件类型过滤
        if (subscription.event !== undefined && event.action !== subscription.event) {
            continue; // 跳过不匹配的事件类型
        }

        // 2.2 检查特定项目订阅
        if ('item' in subscription) {
            if ('keys' in event && !event.keys.includes(subscription.item)) continue;
            if ('key' in event && event.key !== subscription.item) continue;
        }

        // 2.3 获取完整数据（应用订阅的 query 参数）
        try {
            const result = await getPayload(subscription, client.accountability, schema, event);

            // 2.4 如果数据为空（权限过滤后），跳过
            if (Array.isArray(result?.['data']) && result?.['data']?.length === 0) continue;

            // 2.5 发送给客户端
            client.send(fmtMessage('subscription', result, subscription.uid));
        } catch (err) {
            handleWebSocketError(client, err, 'subscribe');
        }
    }
}
```

## 4. 变更事件推送和前端界面更新

### 4.1 服务端推送消息格式

服务端向客户端推送的订阅事件格式：

```typescript
// api/src/websocket/utils/message.ts
{
    type: 'subscription',           // 消息类型
    uid?: string | number,          // 订阅 ID（匹配客户端发送的 uid）
    event: 'init' | 'create' | 'update' | 'delete' | 'unsubscribe',  // 事件类型
    data: any[]                     // 事件数据
}
```

**事件类型说明**:

| 事件类型 | 触发时机 | data 内容 |
|---------|---------|-----------|
| `init` | 订阅成功后立即发送 | 集合的初始数据（如果订阅时未指定 event） |
| `create` | 新项目创建 | 新创建的项目数据 |
| `update` | 项目更新 | 更新后的项目数据 |
| `delete` | 项目删除 | 被删除项目的主键列表 |
| `unsubscribe` | 取消订阅成功 | 空 |

### 4.2 客户端接收事件

客户端通过 `AsyncGenerator` 接收事件：

```typescript
// 使用示例
const { subscription, unsubscribe } = await client.subscribe('articles', {
    query: { fields: ['id', 'title', 'status'] }
});

// 迭代接收事件
for await (const event of subscription) {
    console.log('Event type:', event.event);  // 'init', 'create', 'update', 'delete'
    console.log('Data:', event.data);
    
    // 更新 UI
    switch (event.event) {
        case 'init':
            setArticles(event.data);
            break;
        case 'create':
            addArticle(event.data[0]);
            break;
        case 'update':
            updateArticle(event.data[0]);
            break;
        case 'delete':
            removeArticles(event.data);  // data 是主键数组
            break;
    }
}
```

function receiveUpdate(message: UpdateMessage) {
    // 确保消息顺序正确
    if (message.order > largestUpdateOrder) {
        largestUpdateOrder = message.order;
    } else {
        return;  // 忽略过期消息
    }

    // 更新本地编辑状态
    if (isEqual(message.changes, initialValues.value?.[message.field])) {
        // 如果变更等于初始值，清除编辑状态
        delete edits.value[message.field];
        return;
    }

    // 更新 edits 对象，触发 Vue 响应式更新
    if (!isEqual(message.changes, edits.value[message.field])) {
        edits.value = { ...edits.value, [message.field]: message.changes };
    }
}

## 总结

### 关键设计亮点

1. **基于 WebSocket 的实时通信**:
   - 使用标准 WebSocket 协议
   - 支持自动重连和订阅恢复
   - 多实例部署通过 Redis Pub/Sub 同步

2. **灵活的订阅选项**:
   - 按集合订阅
   - 按事件类型过滤 (create/update/delete)
   - 按特定项目订阅
   - 自定义查询参数 (fields, filter 等)

3. **权限感知**:
   - 事件分发时检查用户权限
   - 应用 `accountability` 过滤数据
   - 确保客户端只能看到有权限的数据

4. **Vue 响应式集成**:
   - 使用 `ref` 和 `computed` 实现响应式状态
   - 数据变更自动触发 UI 更新
   - 协作编辑时实时显示其他用户的操作

### 技术栈

- **传输层**: WebSocket (ws/wss)
- **消息总线**: Redis Pub/Sub (多实例) 或内存 Bus (单实例)
- **客户端 SDK**: TypeScript + AsyncGenerator
- **前端框架**: Vue 3 (Composition API + Reactivity)
- **状态管理**: Pinia (stores)
