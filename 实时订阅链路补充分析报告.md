## 1. GraphQL 订阅完整流程

### 1.1 架构概览

GraphQL 订阅与 REST 订阅共享**同一个事件总线**，但使用不同的协议和消息格式。

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         共享事件总线层                                      │
│  ┌──────────────┐    ┌──────────────────┐    ┌──────────────────────┐  │
│  │ 数据写入操作  │───>│ emitter.onAction │───>│ messenger.publish    │  │
│  │ (Service层)  │    │ (事件钩子)        │    │ ('websocket.event') │  │
│  └──────────────┘    └──────────────────┘    └──────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
┌─────────────────────────────┐    ┌─────────────────────────────────────┐
│      REST 订阅通道           │    │         GraphQL 订阅通道             │
│  (自定义 Directus 协议)      │    │      (graphql-ws 标准协议)          │
├─────────────────────────────┤    ├─────────────────────────────────────┤
│ 端点: /websocket            │    │ 端点: /websocket (复用)              │
│ 消息格式: 自定义 JSON         │    │ 协议: graphql-ws (子协议协商)        │
│ 订阅管理: SubscribeHandler   │    │ 服务端: graphql-ws makeServer       │
└─────────────────────────────┘    └─────────────────────────────────────┘
```

### 1.2 从事件总线到客户端的完整链路

#### 步骤 1: 事件总线绑定

GraphQL 订阅通过 `bindPubSub()` 函数绑定到共享事件总线：

```typescript
// api/src/services/graphql/subscription.ts:11-19
const messages = createPubSub(new EventEmitter());

export function bindPubSub() {
    const messenger = useBus();

    // 监听共享的 'websocket.event' 通道
    messenger.subscribe('websocket.event', (message: Record<string, any>) => {
        // 转发到集合特定的事件：{collection}_mutated
        messages.publish(`${message['collection']}_mutated`, message);
    });
}
```

**关键点**：
- 与 REST 订阅**共享同一个 `websocket.event` 消息总线**
- 将通用事件转发到集合特定的事件名（如 `articles_mutated`）

#### 步骤 2: GraphQL Schema 生成订阅字段

在生成 GraphQL Schema 时，为每个可读集合创建订阅字段：

```typescript
// api/src/services/graphql/schema/read.ts:703-724
const eventName = `${collection.collection}_mutated`;

if (collection.collection in ReadCollectionTypes) {
    // 定义订阅返回类型
    const subscriptionType = schemaComposer.createObjectTC({
        name: eventName,
        fields: {
            key: new GraphQLNonNull(GraphQLID),    // 项目主键
            event: subscriptionEventType,           // 'create' | 'update' | 'delete'
            data: ReadCollectionTypes[collection.collection]!,  // 完整数据
        },
    });

    // 添加到 Subscription 根类型
    schemaComposer.Subscription.addFields({
        [eventName]: {
            type: subscriptionType,
            args: {
                event: subscriptionEventType,  // 可选参数：过滤事件类型
            },
            subscribe: createSubscriptionGenerator(gql, eventName),
        },
    });
}
```

**生成的订阅字段示例**：

```graphql
type Subscription {
    articles_mutated(
        event: EventEnum  # create | update | delete
    ): articles_mutated
}

type articles_mutated {
    key: ID!
    event: EventEnum!
    data: articles
}
```

#### 步骤 3: 订阅生成器实现

`createSubscriptionGenerator` 创建异步生成器来处理订阅：

```typescript
// api/src/services/graphql/subscription.ts:21-85
export function createSubscriptionGenerator(gql: GraphQLService, event: string) {
    return async function* (_x: unknown, _y: unknown, _z: unknown, request: GraphQLResolveInfo) {
        // 解析 GraphQL 查询中的字段选择
        const fields = await parseFields(gql, request);
        // 解析参数（如 event 过滤）
        const args = parseArguments(request);

        // 订阅 PubSub 事件
        for await (const payload of messages.subscribe(event)) {
            const eventData = payload as WebSocketEvent;

            // 事件类型过滤
            if ('event' in args && eventData['action'] !== args['event']) {
                continue; // 跳过不匹配的事件类型
            }

            const schema = await getSchema();

            // 构建订阅对象（用于 getPayload）
            const subscription: Omit<Subscription, 'client'> = {
                collection: eventData['collection'],
                event: eventData['action'],
                query: { fields },  // 使用 GraphQL 选择的字段
            };

            // 根据事件类型处理
            if (eventData['action'] === 'delete') {
                // 删除事件：只有 key，没有数据
                for (const key of eventData.keys) {
                    yield { [event]: { key, data: null, event: eventData['action'] } };
                }
            }

            if (eventData['action'] === 'create') {
                try {
                    subscription.item = eventData['key'];
                    // 获取完整数据（应用权限和字段选择）
                    const result = await getPayload(subscription, gql.accountability, schema, eventData);

                    yield {
                        [event]: {
                            key: eventData['key'],
                            data: result['data'],
                            event: eventData['action'],
                        },
                    };
                } catch {
                    // 权限错误时静默跳过
                }
            }

            if (eventData['action'] === 'update') {
                // 批量更新时，每个 key 单独产出
                for (const key of eventData['keys']) {
                    try {
                        subscription.item = key;
                        const result = await getPayload(subscription, gql.accountability, schema, eventData);

                        yield {
                            [event]: {
                                key,
                                data: result['data'],
                                event: eventData['action'],
                            },
                        };
                    } catch {
                        // 权限错误时静默跳过
                    }
                }
            }
        }
    };
}
```

#### 步骤 4: GraphQL WebSocket 服务器

GraphQL 订阅使用 `graphql-ws` 库实现标准的 GraphQL over WebSocket 协议：

```typescript
// api/src/websocket/controllers/graphql.ts:22-50
export class GraphQLSubscriptionController extends SocketController {
    gql: Server<GraphQLSocket>;
    
    constructor(httpServer: httpServer) {
        super(httpServer, 'WEBSOCKETS_GRAPHQL');
        registerWebSocketEvents();  // 注册事件钩子（与 REST 共享）

        this.server.on('connection', (ws: WebSocket, auth: AuthenticationState) => {
            this.bindEvents(this.createClient(ws, auth));
        });

        // 使用 graphql-ws 创建服务器
        this.gql = makeServer<ConnectionParams, GraphQLSocket>({
            schema: async (ctx) => {
                const accountability = ctx.extra.client.accountability;

                // 动态生成 Schema（考虑用户权限）
                const service = new GraphQLService({
                    schema: await getSchema(),
                    scope: 'items',
                    accountability,
                });

                return service.getSchema();
            },
        });

        bindPubSub();  // 绑定到事件总线

        logger.info(`GraphQL Subscriptions started at ${getAddress(httpServer)}${this.endpoint}`);
    }
}
```

## 2. REST 订阅 vs GraphQL 订阅边界对比

### 2.1 核心差异对比表

| 维度 | REST 订阅 | GraphQL 订阅 |
|------|----------|-------------|
| **协议** | 自定义 Directus WebSocket 协议 | 标准 `graphql-ws` 协议 |
| **端点** | `/websocket` | `/websocket` (复用同一端点) |
| **消息格式** | 自定义 JSON 结构 | 标准 GraphQL 响应格式 |
| **服务端实现** | `SubscribeHandler` 类 | `graphql-ws` + 自定义 PubSub |
| **字段选择** | 通过 `query.fields` 参数 | 通过 GraphQL 选择集 |
| **嵌套查询** | 支持（通过 query 参数） | 原生支持（GraphQL 特性） |
| **类型安全** | 运行时验证 (Zod) | 编译时 + 运行时 (GraphQL Schema) |
| **多订阅管理** | 通过 `uid` 标识 | 通过 graphql-ws 内部管理 |

### 2.5 过滤能力对比

| 过滤维度 | REST 订阅 | GraphQL 订阅 |
|---------|----------|-------------|
| **事件类型** | `event: 'create' \| 'update' \| 'delete'` | `event: EventEnum` 参数 |
| **特定项目** | `item: '123'` | 不支持（需要客户端过滤） |
| **字段选择** | `query.fields` | GraphQL 选择集 |
| **嵌套字段** | 支持（通过 `fields: ['author.name']`） | 原生支持 |
| **数据过滤** | `query.filter` | 不支持（订阅级别无 filter） |
| **权限过滤** | 服务端自动应用 | 服务端自动应用 |

**关键差异说明**：

1. **特定项目订阅**：
   - REST 订阅支持 `item` 参数，只接收特定 ID 的变更
   - GraphQL 订阅不支持此功能，需要客户端在接收后过滤

2. **数据过滤**：
   - REST 订阅支持 `query.filter`，服务端只推送匹配条件的数据
   - GraphQL 订阅不支持订阅级别的 `filter`，所有变更都会推送

3. **嵌套查询**：
   - 两者都支持，但 GraphQL 的语法更自然

### 2.7 边界场景对比

| 场景 | REST 订阅 | GraphQL 订阅 |
|------|----------|-------------|
| **多集合订阅** | 多次调用 `subscribe()` | 单个 subscription 操作多个字段 |
| **连接断开恢复** | SDK 自动重连并恢复订阅 | graphql-ws 需自行处理 |
| **认证过期** | 支持 token 刷新重连 | 需重新建立连接 |
| **批量更新处理** | 单条消息包含所有 keys | 每条 key 单独消息 |
| **权限变更** | 下次事件时检查 | 下次事件时检查 |
| **系统集合订阅** | 部分支持（有例外列表） | 部分支持（有例外列表） |

**多集合订阅示例对比**：


```graphql
    }
```

## 3. 取消订阅回执与常规变更事件的语义区别

### 3.1 消息类型总览

服务端发送的 `subscription` 类型消息有多种 `event` 值，各自语义不同：

| event 值 | 触发时机 | 语义 | data 内容 |
|---------|---------|------|----------|
| `init` | 订阅成功后立即发送 | 初始数据快照 | 符合条件的所有项目数组 |
| `create` | 新项目创建 | 数据变更事件 | 新创建的项目数组 |
| `update` | 项目更新 | 数据变更事件 | 更新后的项目数组 |
| `delete` | 项目删除 | 数据变更事件 | 被删除项目的主键数组 |
| `unsubscribe` | 取消订阅确认 | 操作回执 | 无（或空） |

### 3.2 服务端实现分析

#### 取消订阅回执发送

```typescript
// api/src/websocket/handlers/subscribe.ts:190-198
if (getMessageType(message) === 'unsubscribe') {
    try {
        this.unsubscribe(client, message.uid);

        // 发送取消订阅回执
        client.send(fmtMessage('subscription', { event: 'unsubscribe' }, message.uid));
    } catch (err) {
        handleWebSocketError(client, err, 'unsubscribe');
    }
}
```

#### 常规变更事件发送

```typescript
// api/src/websocket/handlers/subscribe.ts:108-135
async dispatch(event: WebSocketEvent) {
    const subscriptions = this.subscriptions[event.collection];
    if (!subscriptions || subscriptions.size === 0) return;
    
    const schema = await getSchema();

    for (const subscription of subscriptions) {
        // ... 过滤检查 ...
        
        try {
            // 获取完整数据
            const result = await getPayload(subscription, client.accountability, schema, event);

            if (Array.isArray(result?.['data']) && result?.['data']?.length === 0) continue;

            // 发送变更事件
            client.send(fmtMessage('subscription', result, subscription.uid));
        } catch (err) {
            handleWebSocketError(client, err, 'subscribe');
        }
    }
}
```

#### init 事件发送

```typescript
// api/src/websocket/handlers/subscribe.ts:177-184
const data =
    subscription.event === undefined 
        ? await getPayload(subscription, accountability, schema)  // 获取初始数据
        : { event: 'init' };  // 指定了 event 过滤时，只发送 init 标记

// 注册订阅

// 发送初始响应
client.send(fmtMessage('subscription', data, subscription.uid));
```

### 3.3 各事件类型的完整消息格式

#### 1. `init` 事件（订阅确认）

**触发条件**：订阅请求成功处理后

**消息格式**：

```json
{
    "type": "subscription",
    "uid": "sub-123",
    "event": "init",
    "data": [
        { "id": "1", "title": "Article 1" },
        { "id": "2", "title": "Article 2" }
    ]
}
```

**特殊情况**：
- 如果订阅时指定了 `event` 过滤（如 `event: 'create'`），则 `data` 为空，只有 `event: 'init'` 标记
- 这表示订阅已成功，但不发送初始数据快照

```json
{
    "type": "subscription",
    "uid": "sub-123",
    "event": "init"
}
```

#### 2. `create` 事件

**触发条件**：新项目创建

**消息格式**：

```json
{
    "type": "subscription",
    "uid": "sub-123",
    "event": "create",
    "data": [
        { "id": "3", "title": "New Article", "status": "draft" }
    ]
}
```

#### 3. `update` 事件

**触发条件**：项目更新

**消息格式**：

```json
{
    "type": "subscription",
    "uid": "sub-123",
    "event": "update",
    "data": [
        { "id": "1", "title": "Updated Title", "status": "published" }
    ]
}
```

#### 4. `delete` 事件

**触发条件**：项目删除

**消息格式**：

```json
{
    "type": "subscription",
    "uid": "sub-123",
    "event": "delete",
    "data": ["1", "2"]  // 被删除项目的主键数组
}
```

**注意**：`delete` 事件的 `data` 是**主键数组**，不是完整对象数组。

#### 5. `unsubscribe` 事件（取消订阅回执）

**触发条件**：客户端发送 `unsubscribe` 消息后

**消息格式**：

```json
{
    "type": "subscription",
    "uid": "sub-123",
    "event": "unsubscribe"
}
```

**关键特征**：
- 没有 `data` 字段
- 仅作为**操作确认回执**
- 不是数据变更事件

### 3.5 前端消费方式对比

#### SDK 内置处理方式

```typescript
// sdk/src/realtime/composable.ts:420-461
async function* subscriptionGenerator(): AsyncGenerator<SubscriptionOutput> {
    while (subscribed && state.code === 'open') {
        const message = await messageCallback(state.connection);
        
        if (!message) continue;

        // 检查是否为订阅相关消息
        if (
            'type' in message &&
            'uid' in message &&
            message['type'] === 'subscription' &&
            message['uid'] === options.uid  // 匹配订阅 ID
        ) {
            yield message;  // 所有事件都产出
        }
    }
}
```

**SDK 不区分事件类型**，所有 `event` 值的消息都会通过 `AsyncGenerator` 产出。

#### 推荐的消费方式

```typescript
const { subscription, unsubscribe } = await sdk.subscribe('articles', {
    query: { fields: ['id', 'title', 'status'] }
});

for await (const event of subscription) {
    console.log('Event type:', event.event);  // 'init' | 'create' | 'update' | 'delete' | 'unsubscribe'
    
    switch (event.event) {
        case 'init':
            // 订阅成功，可能包含初始数据
            console.log('Subscribed successfully');
            if (event.data) {
                setArticles(event.data);
            }
            break;
            
        case 'create':
            // 新项目创建
            event.data.forEach(item => addArticle(item));
            break;
            
        case 'update':
            // 项目更新
            event.data.forEach(item => updateArticle(item));
            break;
            
        case 'delete':
            // 项目删除 - data 是主键数组！
            event.data.forEach(id => removeArticle(id));
            break;
            
        case 'unsubscribe':
            // 订阅已取消（服务端确认）
            console.log('Subscription ended');
            // 注意：此时 AsyncGenerator 可能还在运行
            // 需要结合 unsubscribe() 调用来判断
            break;
    }
}
```

#### 完整的订阅生命周期管理

```typescript
class SubscriptionManager {
    private subscribed = true;
    private subscription: AsyncGenerator | null = null;
    
    async start() {
        const { subscription, unsubscribe: doUnsubscribe } = await sdk.subscribe('articles');
        this.subscription = subscription;
        
        // 包装 unsubscribe 来设置标志
        this.unsubscribe = () => {
            this.subscribed = false;
            doUnsubscribe();
        };
        
        // 启动消费循环
        this.consume();
    }
    
    private async consume() {
        if (!this.subscription) return;
        
        try {
            for await (const event of this.subscription) {
                if (!this.subscribed) {
                    // 我们已主动取消，忽略后续消息
                    break;
                }
                
                switch (event.event) {
                    case 'init':
                        this.handleInit(event);
                        break;
                    case 'create':
                        this.handleCreate(event);
                        break;
                    case 'update':
                        this.handleUpdate(event);
                        break;
                    case 'delete':
                        this.handleDelete(event);
                        break;
                    case 'unsubscribe':
                        // 服务端已确认取消
                        // 此时 subscribed 应该已经是 false
                        console.log('Server confirmed unsubscribe');
                        break;
                }
            }
        } catch (error) {
            console.error('Subscription error:', error);
        }
    }
    
    unsubscribe: () => void = () => {};
}
```

### 3.6 常见陷阱

#### 陷阱 1: `delete` 事件的 data 格式不同

```typescript
// ❌ 错误：假设 delete 的 data 也是对象数组
for await (const event of subscription) {
    if (event.event === 'delete') {
        event.data.forEach(item => removeArticle(item.id));  // 错误！item 是字符串主键
    }
}

// ✅ 正确：delete 的 data 是主键数组
for await (const event of subscription) {
    if (event.event === 'delete') {
        event.data.forEach(id => removeArticle(id));  // 直接使用 id
    }
}
```

#### 陷阱 2: 忽略 `unsubscribe` 事件与主动取消的关系

```typescript
// ❌ 错误：依赖 unsubscribe 事件来结束循环
let isActive = true;

for await (const event of subscription) {
    if (event.event === 'unsubscribe') {
        isActive = false;
        break;
    }
    // 处理事件...
}

// 问题：如果连接断开，不会收到 unsubscribe 事件
// 应该同时监听连接状态

// ✅ 正确：结合主动标志和事件
let isActive = true;
let connectionClosed = false;

sdk.onWebSocket('close', () => {
    connectionClosed = true;
});

for await (const event of subscription) {
    if (!isActive || connectionClosed) break;
    
    if (event.event === 'unsubscribe') {
        // 服务端确认，但我们可能已经设置了 isActive = false
        break;
    }
    // 处理事件...
}

// 主动取消时
function stop() {
    isActive = false;
    unsubscribe();
}
```

#### 陷阱 3: `init` 事件的 data 可能为空

```typescript
// ❌ 错误：假设 init 总是有 data
for await (const event of subscription) {
    if (event.event === 'init') {
        setArticles(event.data);  // 可能是 undefined！
    }
}

// ✅ 正确：检查 data 是否存在
for await (const event of subscription) {
    if (event.event === 'init') {
        if (event.data) {
            setArticles(event.data);
        } else {
            // 订阅时指定了 event 过滤，没有初始数据
            console.log('Subscribed, no initial data');
        }
    }
}
```

### 3.7 事件类型决策表

| 需求 | 推荐做法 |
|------|---------|
| **初始化本地状态** | 等待 `init` 事件，使用其 `data`（如果有） |
| **处理新增数据** | 监听 `create` 事件，`data` 是完整对象数组 |
| **处理数据更新** | 监听 `update` 事件，`data` 是完整对象数组 |
| **处理数据删除** | 监听 `delete` 事件，`data` 是**主键数组** |
| **确认订阅取消** | 监听 `unsubscribe` 事件，同时结合主动标志 |
| **检测连接断开** | 使用 `onWebSocket('close', callback)` |
