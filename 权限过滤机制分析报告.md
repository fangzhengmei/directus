# Directus 权限过滤机制深度分析报告

## 1. 概述

Directus 的权限系统是一个基于角色（Role）和策略（Policy）的细粒度访问控制系统。权限规则从角色配置一路传递到数据库查询，经历了**配置存储 → 权限解析 → AST 注入 → SQL 生成** 的完整流程。

## 2. 权限规则的数据结构

### 2.1 核心类型定义

权限规则的核心数据结构定义在 `@directus/types` 包中：

```typescript
// packages/types/src/permissions.ts
export type Permission = {
    id?: number;
    policy: string | null;           // 关联的策略 ID
    collection: string;              // 目标集合
    action: PermissionsAction;       // 操作类型: 'create' | 'read' | 'update' | 'delete' | 'share'
    permissions: Filter | null;      // 权限过滤规则（核心）
    validation: Filter | null;       // 数据验证规则
    presets: Record<string, any> | null;  // 字段预设值
    fields: string[] | null;         // 允许访问的字段
    system?: true;
};
```

### 2.2 Filter 类型结构

`Filter` 是权限规则的核心表达形式，支持逻辑组合和字段级操作：

```typescript
// packages/types/src/filter.ts
export type Filter = LogicalFilter | FieldFilter;

// 逻辑操作
export type LogicalFilterOR = { _or: Filter[] };
export type LogicalFilterAND = { _and: Filter[] };

// 字段过滤
export type FieldFilter = {
    [field: string]: FieldFilterOperator | FieldFilter;
};

// 支持的操作符
export type FilterOperator =
    | 'eq' | 'neq' | 'lt' | 'lte' | 'gt' | 'gte'
    | 'in' | 'nin' | 'null' | 'nnull'
    | 'contains' | 'ncontains' | 'icontains'
    | 'between' | 'nbetween'
    | 'empty' | 'nempty'
    | 'intersects' | 'nintersects'
    | 'intersects_bbox' | 'nintersects_bbox';
```

### 2.3 权限规则示例

```json

    "collection": "articles",
    "action": "read",
    "permissions": {
        "_and": [
            { "status": { "_eq": "published" } },

                    { "author": { "_eq": "$CURRENT_USER" } },

    },

```

### 2.4 策略（Policy）与权限的关系

```typescript
// packages/types/src/policies.ts
export interface Policy {
    id: string;
    name: string;
    icon: string;
    description: string | null;
    enforce_tfa: null | boolean;
    ip_access: string[] | null;
    app_access: boolean;      // 是否允许访问应用
    admin_access: boolean;    // 是否为管理员权限
}
```

**关键关系**：
- 一个 **Policy** 可以关联多个 **Permission** 记录
- 每个 **Permission** 记录对应一个特定的 `collection + action` 组合
- 权限通过 `directus_access` 表关联到用户或角色

## 3. 请求处理链路中的权限解析时机

### 3.1 整体流程图

```
HTTP 请求
    ↓
[中间件层]
├── authenticate.ts  → 设置 req.accountability
└── 其他中间件
    ↓
[控制器层]
└── 路由控制器 → 调用相应 Service
    ↓
[服务层]
├── ItemsService.readByQuery()   ──┐
├── ItemsService.createOne()        │
├── ItemsService.updateMany()       │
└── ItemsService.deleteMany()       │
    ↓                               │
[权限处理层]                         │
├── processAst()  ←─────────────────┤  (读取操作)
├── processPayload()  ←─────────────┤  (创建/更新操作)
└── validateAccess()  ←─────────────┘  (删除/验证操作)
    ↓
[AST 执行层]
├── runAst()
│   ├── getDBQuery()
│   │   ├── applyQuery()
│   │   │   ├── joinFilterWithCases()  ← 权限条件与用户查询组合
│   │   │   └── applyFilter()           ← 生成 SQL WHERE 条件
│   │   └── applyCaseWhen()             ← 字段级别权限处理
│   └── Knex 执行
    ↓
[数据库]
└── SQL 查询执行
```

### 3.2 认证中间件：Accountability 的建立

## 4. 权限规则如何转换为 SQL 查询条件

### 4.1 核心处理流程

以 `readByQuery` 为例，权限注入经历以下步骤：

```
1. getAstFromQuery()  → 从用户查询构建 AST
2. processAst()       → 权限注入（核心）
3. injectCases()      → 将权限规则注入 AST 节点
4. runAst()           → 执行 AST
5. joinFilterWithCases()  → 组合用户 filter 与权限 cases
6. applyFilter()      → 生成 SQL WHERE 条件
7. applyCaseWhen()    → 生成字段级 CASE WHEN
```

### 4.2 processAst：权限注入核心

**文件**: `api/src/permissions/modules/process-ast/process-ast.ts`

```typescript
export async function processAst(options: ProcessAstOptions, context: Context) {
    // 1. 从 AST 提取字段映射（哪些集合的哪些字段被访问）
    const fieldMap: FieldMap = fieldMapFromAst(options.ast, context.schema);
    const collections = collectionsInFieldMap(fieldMap);

    // 2. 管理员跳过权限检查
    if (!options.accountability || options.accountability.admin) {
        return options.ast;
    }

    // 3. 获取用户的策略列表
    const policies = await fetchPolicies(options.accountability, context);

    // 4. 获取权限规则（按 action + collection 过滤）
    const permissions = await fetchPermissions(
        { action: options.action, policies, collections, accountability: options.accountability },
        context,
    );

    // 5. 对于非 read 操作，也需要 read 权限来验证关联字段
    const readPermissions = options.action === 'read'
        ? permissions
        : await fetchPermissions({ action: 'read', policies, collections, accountability }, context);

    // 6. 验证字段存在性和权限
    for (const [path, { collection, fields }] of fieldMap.other.entries()) {
        validatePathPermissions(path, permissions, collection, fields);
    }

    // 7. 注入权限 cases 到 AST
    injectCases(options.ast, permissions);

    return options.ast;
}
```

### 4.3 injectCases：将权限注入 AST 节点

**文件**: `api/src/permissions/modules/process-ast/lib/inject-cases.ts`

```typescript
export function injectCases(ast: AST, permissions: Permission[]) {
    ast.cases = processChildren(ast.name, ast.children, permissions);
}

function processChildren(
    collection: string,
    children: (NestedCollectionNode | FieldNode | FunctionFieldNode)[],
    permissions: Permission[],
) {
    const requestedKeys = uniq(children.map(getUnaliasedFieldKey));
    
    // 获取权限规则转换后的 cases
    const { cases, caseMap, allowedFields } = getCases(collection, permissions, requestedKeys);

    for (const child of children) {
        const fieldKey = getUnaliasedFieldKey(child);
        const globalWhenCase = caseMap['*'];
        const fieldWhenCase = caseMap[fieldKey];

        // 如果没有完全访问权限，设置 whenCase
        if (!allowedFields.has('*') && !allowedFields.has(fieldKey)) {
            child.whenCase = [...(globalWhenCase ?? []), ...(fieldWhenCase ?? [])];
        }

        // 递归处理关联字段（m2o, o2m, a2o）
        if (child.type === 'm2o') {
            child.cases = processChildren(child.relation.related_collection!, child.children, permissions);
        }
        // ... o2m, a2o 类似处理
    }

    return cases;
}
```

### 4.4 getCases：权限规则到 Cases 的转换

**文件**: `api/src/permissions/modules/process-ast/lib/get-cases.ts`

```typescript
export function getCases(collection: string, permissions: Permission[], requestedKeys: string[]) {
    const permissionsForCollection = permissions.filter((p) => p.collection === collection);
    
    const rules = dedupeAccess(permissionsForCollection);
    const cases: Filter[] = [];
    const caseMap: Record<FieldKey, number[]> = {};

    let index = 0;

    for (const { rule, fields } of rules) {
        // 检查当前规则的字段是否与请求的字段有交集
        if (requestedKeys.length > 0 && 
            fields.has('*') === false &&
            Array.from(fields).every((field) => requestedKeys.includes(field) === false)) {
            continue;
        }

        if (rule === null) continue;

        cases.push(rule);  // 将权限 Filter 加入 cases

        // 映射每个字段对应的 case 索引
        for (const field of fields) {
            caseMap[field] = [...(caseMap[field] ?? []), index];
        }

        index++;
    }

    // 识别无任何条件限制的字段（完全访问）
    const allowedFields = new Set(
        permissionsForCollection
            .filter((permission) => hasItemPermissions(permission) === false)
            .map((permission) => permission.fields ?? [])
            .flat(),
    );

    return { cases, caseMap, allowedFields };
}
```

### 4.5 joinFilterWithCases：组合用户查询与权限条件

**文件**: `api/src/database/run-ast/lib/apply-query/join-filter-with-cases.ts`

```typescript
export function joinFilterWithCases(filter: Filter | null | undefined, cases: Filter[]) {
    if (cases.length > 0 && !filter) {
        // 只有权限条件：使用 OR 组合所有权限规则
        return { _or: cases };
    } else if (filter && cases.length === 0) {
        // 只有用户查询
        return filter ?? null;
    } else if (filter && cases.length > 0) {
        // 两者都有：用户条件 AND (权限条件 OR 权限条件 ...)
        return { _and: [filter, { _or: cases }] };
    }
    return null;
}
```

**SQL 逻辑对应**：
```sql
-- 用户查询: WHERE status = 'published'
-- 权限条件: (author = CURRENT_USER) OR (is_public = true)

-- 组合后:
WHERE status = 'published' 
  AND (author = $1 OR is_public = true)
```

### 4.6 applyCaseWhen：字段级别权限的 SQL 生成

**文件**: `api/src/database/run-ast/utils/apply-case-when.ts`

对于字段级别的权限，Directus 使用 `CASE WHEN` 语句：

```typescript
export function applyCaseWhen(
    { columnCases, table, aliasMap, cases, column, alias, permissions }: ApplyCaseWhenOptions,
    { knex, schema }: ApplyCaseWhenContext,
): Knex.Raw {
    const caseQuery = knex.queryBuilder();
    
    // 应用权限条件生成 WHERE 子句
    applyFilter(knex, schema, caseQuery, { _or: columnCases }, table, aliasMap, cases, permissions);

    const compiler = knex.client.queryCompiler(caseQuery);
    
    // 提取 WHERE 条件
    const sqlParts = [];
    for (const statement of compiler.grouped.where) {
        const val = compiler[statement.type](statement);
        if (val) {
            if (sqlParts.length > 0) sqlParts.push(statement.bool);
            sqlParts.push(val);
        }
    }

    const sql = sqlParts.length > 0 ? sqlParts.join(' ') : '1';
    const bindings = [...caseQuery.toSQL().bindings, column];

    // 生成 CASE WHEN 语句
    let rawCase = `(CASE WHEN ${sql} THEN ?? END)`;
    if (alias) {
        rawCase += ' AS ??';
        bindings.push(alias);
    }

    return knex.raw(rawCase, bindings);
}
```

**生成的 SQL 示例**：
```sql
-- 对于有权限限制的字段，使用 CASE WHEN
SELECT 
    id,
    CASE WHEN (author = $1 OR is_public = true) THEN title END AS title,
    CASE WHEN (author = $1 OR is_public = true) THEN content END AS content
FROM articles
WHERE status = 'published'
  AND (author = $2 OR is_public = true)
```

## 5. 不同操作类型的权限处理差异

### 5.1 操作类型概览

| 操作类型 | 核心处理函数 | 权限检查重点 | SQL 影响 |
|---------|-------------|-------------|----------|
| **read** | `processAst` + `runAst` | 集合权限 + 字段权限 + 项目权限 | WHERE 条件 + CASE WHEN |
| **create** | `processPayload` | 字段权限 + 验证规则 + 预设值 | 无（数据验证阶段） |
| **update** | `processPayload` + `validateAccess` | 字段权限 + 验证规则 + 项目权限 | 无（数据验证阶段） |
| **delete** | `validateAccess` | 项目权限（必须验证具体 PK） | 无（验证查询阶段） |

### 5.2 Read 操作：完整的权限过滤

**核心流程**：

```typescript
// items.ts:readByQuery
async readByQuery(query: Query, opts?: QueryOptions): Promise<Item[]> {
    // 1. 从查询构建 AST
    let ast = await getAstFromQuery(
        { collection: this.collection, query: updatedQuery, accountability: this.accountability },
        { schema: this.schema, knex: this.knex },
    );

    // 2. 注入权限到 AST（核心）
    ast = await processAst(
        { ast, action: 'read', accountability: this.accountability },
        { knex: this.knex, schema: this.schema },
    );

    // 3. 执行 AST（生成带权限的 SQL）
    const records = await runAst(ast, this.schema, this.accountability, {
        knex: this.knex,
        stripNonRequested: opts?.stripNonRequested !== undefined ? opts.stripNonRequested : true,
    });

    return records;
}
```

**权限影响点**：
1. **行级过滤**：`cases` 被加入 WHERE 条件，只返回符合权限的记录
2. **字段级过滤**：`whenCase` 被用于 `CASE WHEN`，无权限字段返回 `NULL`
3. **关联字段**：递归处理 m2o、o2m、a2o 关联的权限

### 5.3 Create 操作：字段权限与数据验证

**核心处理**：`processPayload`

**文件**: `api/src/permissions/modules/process-payload/process-payload.ts`

```typescript
export async function processPayload(options: ProcessPayloadOptions, context: Context) {
    let permissions;

    if (!options.accountability.admin) {
        const policies = await fetchPolicies(options.accountability, context);
        
        permissions = await fetchPermissions(
            { action: options.action, policies, collections: [options.collection], accountability },
            context,
        );

        if (permissions.length === 0) {
            throw createCollectionForbiddenError('', options.collection);
        }

        // 1. 检查字段权限
        const fieldsAllowed = uniq(permissions.map(({ fields }) => fields ?? []).flat());
        
        if (fieldsAllowed.includes('*') === false) {
            const fieldsUsed = Object.keys(options.payload);
            const notAllowed = difference(fieldsUsed, fieldsAllowed);
            
            if (notAllowed.length > 0) {
                throw createFieldsForbiddenError('', options.collection, notAllowed);
            }
        }
    }

    // 2. 应用预设值 (presets)
    const presets = (permissions ?? []).map((p) => p.presets);
    const payloadWithPresets = assign({}, ...presets, options.payload);

    // 3. 收集验证规则
    const permissionValidationRules = permissions.map(({ validation }) => validation);
    const fieldValidationRules = [...];  // 字段级验证（非空、schema validation 等）
    
    const validationRules = [...fieldValidationRules, ...permissionValidationRules]
        .filter((rule): rule is Filter => rule !== null && Object.keys(rule).length > 0);

    // 4. 执行数据验证
    if (validationRules.length > 0) {
        const validationErrors = validatePayload({ _and: validationRules }, payloadWithPresets);
        if (validationErrors.length > 0) throw validationErrors;
    }

    return payloadWithPresets;
}
```

**Create vs Read 的关键差异**：

| 维度 | Read | Create |
|------|------|--------|
| 权限规则用途 | 过滤查询结果 | 验证输入数据 |
| 应用时机 | 查询执行时 | 数据写入前 |
| SQL 影响 | WHERE + CASE WHEN | 无（纯逻辑验证） |
| `permissions` 字段 | 行级过滤条件 | 不使用（Create 无行级概念） |
| `validation` 字段 | 不使用 | 数据验证规则 |
| `presets` 字段 | 不使用 | 自动填充字段值 |

### 5.4 Update 操作：双重权限检查

Update 操作是最复杂的，需要：
1. **字段权限检查**（哪些字段可以修改）
2. **项目权限验证**（有权修改哪些记录）
3. **数据验证**（新值是否符合规则）

**关键代码**：

```typescript
// items.ts 中 updateMany 的简化流程
async updateMany(keys: PrimaryKey[], data: Partial<Item>, opts?: MutationOptions) {
    // 1. 首先验证是否有权限修改这些项目
    await validateAccess(
        { accountability: this.accountability, action: 'update', collection: this.collection, primaryKeys: keys },
        { schema: this.schema, knex: this.knex },
    );

    // 2. 处理 payload（字段权限 + 验证 + presets）
    const payloadWithPresets = await processPayload(
        { accountability: this.accountability, action: 'update', collection: this.collection, payload: data, nested },
        { schema: this.schema, knex: trx },
    );

    // 3. 执行更新
    await trx(this.collection)
        .whereIn(primaryKeyField, keys)
        .update(payloadWithTypeCasting);
}
```

**validateItemAccess 内部实现**：

```typescript
// validate-item-access.ts
export async function validateItemAccess(options: ValidateItemAccessOptions, context: Context) {
    // 构建一个特殊的 AST 来验证权限
    const ast: AST = {
        type: 'root',
        name: options.collection,
        query: { limit: options.primaryKeys!.length },
        children: options.fields?.map((field) => ({ 
            type: 'field', name: field, fieldKey: field, whenCase: [], alias: false 
        })) ?? [],
        cases: [],
    };

    // 注入权限
    await processAst({ ast, ...options }, context);

    // 添加 PK 过滤
    if (options.primaryKeys) {
        ast.query.filter = { [primaryKeyField]: { _in: options.primaryKeys! } };
    }

    // 执行查询验证
    const items = await fetchPermittedAstRootFields(ast, {
        schema: context.schema,
        accountability: options.accountability,
        knex: context.knex,
        action: options.action,
    });

    // 检查返回数量是否匹配
    const expectedCount = options.primaryKeys!.length;
    const hasAccess = items && items.length === expectedCount;

    return { accessAllowed: hasAccess };
}
```

**验证原理**：通过执行一个带有权限注入的查询，检查是否能返回所有请求的 PK。如果返回数量少于请求数量，说明某些记录无权限。

### 5.5 Delete 操作：项目级权限验证

Delete 操作相对简单，只需要验证项目级权限：

```typescript
// items.ts:deleteMany 简化
async deleteMany(keys: PrimaryKey[], opts?: MutationOptions) {
    // 验证是否有权删除这些项目
    await validateAccess(
        { accountability: this.accountability, action: 'delete', collection: this.collection, primaryKeys: keys },
        { schema: this.schema, knex: this.knex },
    );

    // 执行删除
    await trx(this.collection).whereIn(primaryKeyField, keys).delete();
}
```

**Delete vs Update 的差异**：

| 维度 | Delete | Update |
|------|--------|--------|
| 字段权限 | 不检查 | 检查（哪些字段可修改） |
| 数据验证 | 不执行 | 执行（新值验证） |
| 预设值 | 不应用 | 应用 |
| 权限规则 | 仅 `permissions` (行级) | `permissions` + `validation` + `presets` |

| 文件路径 | 功能描述 |
|---------|---------|
| `api/src/services/items.ts` | ItemsService 核心业务逻辑 |
| `api/src/middleware/authenticate.ts` | 认证中间件，建立 accountability |

## 7. 总结

### 7.1 权限传递完整链路

```
角色配置 (directus_roles)
    ↓
策略关联 (directus_access)
    ↓
权限规则 (directus_permissions)
    │
    ├─── 存储形态: Filter JSON
    │
    ↓
请求到达
    ↓
authenticate 中间件 → accountability (user, role, admin, ip...)
    ↓
ItemsService 方法调用
    │
    ├── readByQuery()
    │   ├── getAstFromQuery()
    │   ├── processAst()
    │   │   ├── fetchPolicies()
    │   │   ├── fetchPermissions()
    │   │   ├── validatePathPermissions()
    │   │   └── injectCases()  ← 权限注入 AST
    │   └── runAst()
    │       ├── getDBQuery()
    │       │   ├── joinFilterWithCases()  ← 组合查询条件
    │       │   ├── applyFilter()           ← 生成 WHERE
    │       │   └── applyCaseWhen()         ← 生成 CASE WHEN
    │       └── Knex 执行
    │
    ├── createOne()/updateOne()
    │   └── processPayload()
    │       ├── 字段权限检查
    │       ├── 预设值应用
    │       └── 数据验证
    │
    └── deleteMany()/updateMany()
        └── validateAccess()
            └── validateItemAccess()
                └── 通过查询验证 PK 权限
```

### 7.2 核心设计亮点

1. **AST 抽象层**：通过 AST 统一处理权限注入，隔离了业务逻辑与 SQL 生成
2. **Case/When 机制**：巧妙使用 SQL 的 CASE WHEN 实现字段级权限，无需多次查询
3. **Filter DSL**：统一的 Filter 表达式语言，同时用于权限规则和用户查询
4. **动态变量支持**：支持 `$CURRENT_USER`、`$NOW` 等动态变量，运行时解析
5. **缓存优化**：`fetchRawPermissions` 带缓存，避免频繁查询权限表

### 7.3 不同操作的权限矩阵

| 操作 | 集合权限 | 字段权限 | 项目权限 | 验证规则 | 预设值 |
|------|---------|---------|---------|---------|--------|
| **read** | ✅ | ✅ (CASE WHEN) | ✅ (WHERE) | ❌ | ❌ |
| **create** | ✅ | ✅ (字段白名单) | ❌ | ✅ | ✅ |
| **update** | ✅ | ✅ (字段白名单) | ✅ (PK 验证) | ✅ | ✅ |
| **delete** | ✅ | ❌ | ✅ (PK 验证) | ❌ | ❌ |
